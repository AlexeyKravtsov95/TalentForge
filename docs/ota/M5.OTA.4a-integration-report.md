# M5.OTA.4a — publisher ↔ client integration report

Date: 2026-10-18. Base: `origin/main` @ `24790ab` (PR #42, #43, #44 merged). Production OTA stays
disabled in every build; nothing was published anywhere but local directories.

Every result below is one of **PASSED** (run here, passed), **FAILED** (run here, failed),
**BLOCKED** (cannot run without something outside this repository) or **NOT RUN** (could run, was
not run in this milestone). Nothing is reported as passed by inference from another check.

## 1. What was integrated

* **Wire contract v1: unchanged.** No schema, model, fixture or conformance case changed
  (`scripts/sync_mobile_ota_fixtures.py --check`: 70 files, 64 cases in sync). This milestone only
  connects the two implementations.
* **The real publisher → the real client.** `scripts/ota_staging_stand.py prepare` runs the M5.OTA.2
  CLI (`build-release`, `validate` G1–G8, `stage`, `rollback` + `sign` + `attach-signature`,
  `verify-live`) over the committed `data/` of a commit on `origin/main`, signs every staging catalog
  with an ephemeral `tf-staging-local-<hex>` key generated outside the repository, and issues an
  ephemeral TLS chain. `OtaStagingE2ETest` serves those exact bytes over HTTPS and runs the M5.OTA.3
  client: the configuration through `OtaConfig.resolve` (the app path, not `forTesting`), the
  `HttpURLConnection` fetcher with explicit trust in the stand's CA only, `java.security` ECDSA, the
  `java.nio` store and the app's repositories as validator. No mock catalog, and no Python verdict is
  fed to Kotlin.
* **Client changes (small; behaviour-neutral for every existing build):**
  `PlatformBlobFetcher(sslSocketFactory = …)` and `pinnedTrustSocketFactory(pem)` — a socket factory
  whose only roots are the given certificates, with certificate and hostname verification untouched;
  `talentforge.ota.android.staging.trustAnchor` for debug builds; `checkReleaseOtaSettings` stops any
  Android release variant while a staging setting is set. Defaults are unchanged: no base URL, no
  keys, OTA disabled.
* **One command:** `scripts/ota_integration_check.sh` (Python baseline, drift, stand, interop,
  `:shared:jvmTest`, `:composeApp:desktopTest` with both opt-in suites, and a verdict that both suites
  ran with 0 skipped).

## 7. Known limitations and findings

* **Not public HTTPS.** The stand is local TLS with its own CA: it proves the two implementations and
  the TLS path, not a CDN. Remote staging needs OD-1 (hosting) and OD-2 (key custody):
  [staging-setup.md](staging-setup.md) §6.
* **Device downloads are small today** (§4.1): every published build is bundled.
* **A duplicate catalog GET at a cold start** (Android step 6): `onAppStarted` and the first
  `ON_START` both trigger a check, and the second runs after the first has finished. Harmless (one
  ≈ 1.4 KB request), outside this milestone; a candidate fix for M5.OTA.4b.
* **The About privacy text** still says the app "works offline, without an account…" without
  mentioning OTA network access; it must be revised before OTA is enabled (OD-4, already listed by
  M5.OTA.3).
* **iOS** stays disabled and has no staging trust anchor (none is needed for a public-PKI staging
  origin); the iOS gate (test-plan §6C, physical device) is unchanged.
* **ADR-0002** recommends parallelism 8 and origin gzip; neither is applied here.
