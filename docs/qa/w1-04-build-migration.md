# W1.04 — копирование билда на активный патч

Копирование доступно в меню билда в библиотеке и редакторе, если активный на устройстве патч Forever численно новее записанного в билде. Сравниваются все четыре компонента версии. Из библиотеки можно сразу открыть созданную копию. При запуске из редактора открывается редактор копии.

## Как сопоставляются таланты

1. Приложение читает исходную запись и точные версии данных из одного снимка. Репозиторий датасетов сверяет документ с манифестом. Allocation engine дополнительно проверяет структуру деревьев и исходное распределение.
2. Для переноса должны совпасть игра, токен и числовой идентификатор класса, устойчивый `treeId` и валюта очков. Дерево дополнительно должно иметь хотя бы один талант с подтверждённой идентичностью в обеих версиях. При отсутствии однозначного дерева перенос блокируется.
3. Переносятся только узлы с тем же `nodeId`, типом, флагами и идентификатором заклинания, а также с той же единственной записью по `entryId`, `definitionId`, `spellId` и типу записи. Названия, координаты, иконки, описания и числовые эффекты могут меняться. Для подтверждённых записей запрос рангов ограничивается новым максимумом.
4. Allocation engine заново покупает запрошенные ранги, начиная с пустого дерева. Проходы идут по возрастанию `nodeId` и повторяются, пока покупки открывают дополнительные ранги и остаются очки. Если бюджет уменьшился, этот порядок разрешает конкуренцию за последние очки. Итог независимо проверяется через `validate()`. Освобождённые очки остаются для ручного распределения.
5. Предпросмотр читает библиотеку и датасеты. Подтверждение ждёт autosave, сверяет исходную запись, активный снимок и хеш целевого документа. Если исходник или снимок изменился, требуется новый предпросмотр. Репозиторий записывает уже названную копию с новым `localId` одной операцией. Исходная запись, включая отметку избранного и отметки времени, сохраняется. Копия создаётся без отметки избранного.

Деревья с изменившимся `treeId` требуют подтверждённой связи в данных. Изменившийся идентификатор записи также блокирует её перенос даже при совпадающем названии. Проверка prerequisites использует существующие правила движка. Статус `EDGE-ACTIVE` и `EDGE-SUF` описан в [семантике распределения](../talent-allocation-semantics.md).

## Данные и результаты

| Данные | Проверка | Результат |
| --- | --- | --- |
| Канонический Warrior, `1.60.1.70959 → 1.60.1.71037` | Билд заполнен через движок до 51 очка. Целевой билд проверен независимо. | 51 перенесено, 0 потеряно, 0 свободно. После экспорта и декодирования TF1 все allocations и целевая версия совпали. |
| Warrior PvP, `1.60.1.70374 → 1.60.1.70450` | 13 очков из закреплённой TF1-фикстуры. | 13 перенесено, 0 потеряно, 38 свободно. |
| Druid Raid, `1.60.1.70009 → 1.60.1.70450` | 51 очко из закреплённой TF1-фикстуры. | 48 перенесено, 3 потеряно, 3 свободно. Исходный «Король джунглей» потерял 3 ранга из-за изменения записи. |
| Исходный билд `1.60.1.70010` | Сохранённая запись с отсутствующим локальным датасетом. | Локализованная причина, доступна отмена, копия отсутствует. |
| Синтетические документы | Удаление узла, замена ID или spell ID записи, уменьшение ранга и бюджета, изменение prerequisite и tier gate. | Переносятся допустимые ранги. Для каждого потерянного ранга отображается затронутый талант и причина. Перестановка исходных allocations даёт тот же результат. |
| Недопустимая версия или структура | Текущий или более новый патч, несовместимый класс, неоднозначное дерево, отсутствующий или повреждённый документ, некорректный исходный билд. | Перенос отклоняется. Для текущего и более нового патча действие скрыто. |
| Ошибки между предпросмотром и записью | Новая OTA-ревизия того же патча, изменение распределения или имени, незавершённый или неуспешный autosave, отказ локальной записи. | Требуется повторный просмотр либо успешное сохранение исходных правок. При отказе записи payload библиотеки совпадает побайтно. |
| Подтверждение и отмена | Повторный Confirm, отмена полного, частичного и заблокированного сценариев, повторное открытие библиотеки после перезапуска. | Одно подтверждение создаёт одну запись. Отмена сохраняет прежний payload. После перезапуска обе записи доступны. |

## Интерфейс

[Скриншоты](../screenshots/w1-04-build-migration/) включают исходный билд в библиотеке, меню, полный и частичный предпросмотры, сообщение об отсутствующем датасете и обе записи после подтверждения. Серии `en-01…06` и `ru-01…06` сняты с общего интерфейса Compose. Скриншоты `ru-07…08` показывают прокрученный предпросмотр при 200% размере текста.

- Compose Desktop. EN и RU, портрет 390 × 844 dp, доступность подтверждения и редактирования имени также при 320 × 568 dp, 740 × 360 dp и 820 × 1180 dp с масштабом шрифта 200%.
- Android Emulator. Английский полный перенос, отказ при отсутствующих данных и проверка записи после холодного запуска. Русский частичный перенос 48 из 51 очка.
- iOS Simulator 26.4.1. На iPhone 17 Pro в портрете прошли английский полный перенос и проверка после холодного запуска. На iPad Air 11-inch (M4) в landscape прошли русский частичный перенос, сообщение об отсутствующем датасете и отмена. Оба прохода выполнены через XCTest.

Скриншоты Compose можно переснять из `mobile/`.

```bash
./gradlew :composeApp:desktopTest --tests '*BuildMigrationUiTest*' \
  -Dtalentforge.w104.screenshots="$PWD/../docs/screenshots/w1-04-build-migration"
```

## Локальные проверки

- `python3 scripts/sync_mobile_datasets.py --check` — 50 файлов пяти встроенных версий совпали с каноническими данными.
- `./gradlew :shared:jvmTest` — успешно, включая реальный переход 70959 → 71037.
- `./gradlew :composeApp:desktopTest --tests '*BuildMigration*'` — целевые регрессии и проверка контроллера.
- `./gradlew :composeApp:assembleDebug` — сборка Android. Изолированная сборка для эмулятора использовала `-Ptalentforge.applicationIdSuffix=.w104qa`.
- `./gradlew :composeApp:linkDebugFrameworkIosArm64 :composeApp:linkDebugFrameworkIosSimulatorArm64 :shared:iosSimulatorArm64Test --no-parallel` — успешно.
- `xcodebuild -project iosApp.xcodeproj -scheme iosApp -configuration Debug -destination 'generic/platform=iOS Simulator' -derivedDataPath build CODE_SIGNING_ALLOWED=NO ARCHS=arm64 build` — успешно.
- `mypy` — 129 файлов без ошибок. Общий запуск Ruff захватил локальный каталог `.tf-transfer` с двумя нарушениями. Повторный запуск Ruff и проверки форматирования с исключением этого каталога прошёл.
- Полный локальный `pytest -q` прерван после исчерпания места в каталоге временных данных. Для полного прогона используется GitHub Actions.
